# A21 普通金币拍卖行

## 运行与所有权

`ServerRuntimeBuilder.ConfigureAuctionRuntime` 在接收游戏包前装配一个全频道共享的 `AuctionRuntime`。默认关闭新交易入口；`AUCTION_ENABLED=1` 才启用。关闭入口或使用 `AUCTION_RECOVERY_ONLY` 构建仍执行已有订单恢复、到期清算和角色删除保护。周期工作复用 `ClockService`，启动时先恢复未决操作，再处理到期订单。

在线资产只使用当前 session 的 owned `InventoryLease`，沿现有库存、钱包、系统邮件和审计事务提交；离线到期使用同一资产提交器。订单库的 Prepared 意图、公用业务库的永久 receipt、订单库的完成状态依次持久化。两个文件之间没有原子事务；结果未知时保留 reservation、角色写围栏和原 operation UUID，由恢复流程核对 receipt，不能凭超时重新扣款。

三个独立文件均在组合根显式初始化，不增加公用迁移编号，不包含默认玩家、账号鉴权或私有业务表：

| 路径环境变量 | 默认值 | 内容 |
| --- | --- | --- |
| `AUCTION_DATABASE_PATH` | `Data/auction.db` | 订单、托管、不可变操作日志、交付索引、后台请求/调整审计和运营配置；基线 `a21-auction-v1`、版本1 |
| `AUCTION_HISTORY_DATABASE_PATH` | 拍卖业务库同目录的 `auction-history.db` | 可从操作日志重建的成交历史投影；基线 `a21-auction-history-v1`、版本1 |
| `ACCOUNT_TUTORIAL_DATABASE_PATH` | `Data/account-tutorial.db` | 账号教程标记；基线 `a21-account-tutorial-v1`、版本1 |

现有未知文件、缺失基线、未知版本或同版本不同结构均拒绝采用。部署前备份这些文件与公用库存库，并保留配套源码、二进制和完整启动配置；回滚二进制不能回滚玩家数据库。恢复构建也必须能识别当前 schema。

## 成交、物品与历史

费用是明确的服务端产品规则：普通5%、优惠3%，逐次成交按累计应收费用向下取整后的差额扣除；单笔押金10000。24/48小时期限、费率和账号配额5/30在上架时确定，48小时需要优惠权益。优惠到期不改旧订单。全部售出或到期退押金一次，主动撤回不退，有人出价后不能撤回。同账号不能自买；同角色加价只增加托管差额，被超价退原款。按件购买限没有竞价的固定单价订单，不自动延长竞拍时间。

`AuctionItemCodec` 保存完整99字节原生实例、完整时装/宠物详情及扩展 JSON。原生列表显示投影不能用来重建交付实例。上游原生实例适配器只接受空扩展对象，未知扩展严格拒绝；有额外实例状态的部署必须提供匹配的适配器。拍卖来源邮件启用严格详情领取，缺失或损坏附件不得退化成模板新物品。

可交易资格仅开放已有 A21 证据覆盖的范围。当前资格及按件价格 profile 绑定 PVF SHA256 `963cd331342a0066c01cb189ec2cd822b8b8206065b109ec63ca664adb3da8d8`；换资源必须重新建立兼容证据。仅看到相似模板或客户端能显示物品，不构成放行依据。当前支持的材料 profile 为3028/3053/3156；装备及四个永久腰部时装 profile 的额外条件见 `AuctionNativeListingRuleResolver`。时装合成详情自测不代表自然实例已经完成原生交易验收。PVF和客户端不随本贡献分发。

`IAuctionTradeHistoryReader` 默认由独立 SQLite 实现。只投影已提交的买断、按件成交及有资金竞价到期成交，不把出价、撤单、流拍或后台修复当成交。记录商品、数量、成交总额、手续费和买卖双方，按账号与角色双重限定查询。时间为冻结成交意图的 `CreatedAtUnix`，重启恢复不改写为恢复时间。按来源 sequence 倒序分页，游标绑定查询账号和角色；每页1至100条。

来源身份、终态和结果哈希发生变化时拒绝覆盖。来源观察、成交和扫描进度在历史库同一事务提交，Prepared/Quarantined 旧洞独立轮转回查，晚于扫描进度完成的操作也只入账一次。运行时历史投影失败不会改变已提交交易、再次扣款或再次发邮件；原操作日志保留以供后续补齐。历史库不拥有金币、押金或物品。原生历史请求和前端呈现仍未接入。

## 后台命令与 CLI

管理业务在原游戏进程内执行。Windows 本机入口是 `DfoServer.A21.Auction.v1`，仅当前系统用户可访问，设置 `AUCTION_ADMIN_PIPE_ENABLED=1` 才建立监听。协议为单连接、单行 UTF-8 JSON，最大64 KiB。CLI在 `Tool/AuctionAdmin/cli.py`，只转发请求，不打开数据库，不自动重试写入。

```powershell
python Tool/AuctionAdmin/cli.py capabilities
python Tool/AuctionAdmin/cli.py capabilities --data '{"command":"orders.patch"}'
python Tool/AuctionAdmin/cli.py orders.get --data '{"orderId":1}'
python Tool/AuctionAdmin/cli.py --input reviewed-request.json --apply
```

完整 envelope：`requestId`、`operation="auction"`、`targetAccountId`/`targetCharacterId`（需要角色上下文时）、`dryRun`，以及 `args.command/operator/reason/data`。`--input` 不与其他 envelope 构造参数混用。

写入默认 dry-run；实际执行需要 `--apply`、稳定 requestId、operator、reason。先读取 `orders.get` 获取 expectedVersion/expectedHash，再预览修改，确认资产差额后使用同一审核过的内容执行。非零资产调整需明确 `allowAssetAdjustment` 和预览生成的 `expectedAdjustmentHash`。同 requestId 的内容不可变；结果未知时查询该 requestId，不能换 ID 重试。

`capabilities` 是命令与字段 schema 的唯一真源，当前31条命令：订单/操作/交付/库存/邮件查询，上架、出价、买断、按件购买、撤回、到期、批量到期、恢复，订单/托管修正、关闭/重开、补偿交付，配置读取/修改、审计查询、补偿撤销、QA种子/清理及未决操作解析。订单字段可通过受审计的结构化修改接口维护；不提供绕过资产凭据的原始 SQL。大型实例和审计通过 chunkOffset/chunkBytes 分块返回，后续分块必须携带首块 SHA256，并在重组完整字节后校验，不截断结果。

HTTP由配套 GM 工具桥接 `/api/auction/commands`、`/api/auction/capabilities`、`/api/auction/schema`，复用其原有登录和权限，且仅转发 auction 到同一游戏管道。CLI使用 `--transport http --base-url https://YOUR-GM-ORIGIN --password-file PATH`，也可从 `AUCTION_ADMIN_HTTP_PASSWORD` 读取口令；不要把口令写进请求文件或命令行参数。桥接不打开游戏数据库、不实现另一套交易逻辑。

## A21 协议证据与教程

CMD/NOTI名称和数值统一引用 `PacketTypesA21.cs`。`AuctionOrdinaryBodyBuilder` 对应客户端 `01189FB0` 普通服务；记录编解码、13字节卖家名尾、搜索和原生列表适配由对应 Builder/Parser 自测固定。资格证据入口 `0232FD90`，auction-free 经 CB4/2E0A → model flag15 → item2C9；equipment type 经 B77 → model3C0 → item60C；cash 经 C3A/2E07 → model1C → item6C。普通服务的第四个视图是本地属性筛选，不是交易历史，不能借它推断历史协议。

教程使用独立账号 flag8。客户端正常关闭和 Finish 均经 `00ACBA40 → 00ACB860` 发送 mode1，服务端保存该账号选择，不要求最后一页才保存。`ACCOUNT_TUTORIAL_INFO` 在 `SELECT_CHARACTER` ACK 后、首次 `USERINFO` 前发送单份 `u8 count + flags`，由 `00ACEA60` 恢复账号集合。角色教程标记与奖励保持独立；未知 mode 和账号标记越界拒绝。

## 验证入口

构建要求0 warning/0 error。先设置当前兼容 `PVF_ARCHIVE_PATH`，串行运行 `--selftest-auction-database`、`--selftest-auction-trade-history`、`--selftest-auction-runtime` 和 `--selftest-all`。CLI离线合同验证：`python -m unittest discover -s Tool/AuctionAdmin -p test_client.py`。SelfTest不启动第二套游戏或GM服务。原生教程关闭/完成后重登和首次退出副本已由人工确认；原生竞价、最高出价人买断补差、退款和两类自然到期已有验收。贡献版移除了私有实例适配，不能把原私有扩展的验收描述为社区部署上已完成的测试。
